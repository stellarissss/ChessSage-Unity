## 1. 地理骨架

### 1.1 整体形态

大陆是一块**东西略长、北岸平直、西南深凹、东南伸出半岛**的不规则陆块，外海环绕四周。四条骨架控制整体读图：

1. **北岸**：几乎平直，纬度 `y ≈ 6~8`，雪原直抵海岸，形成「天墙—冰原—海」三层横向条带。
2. **西岸**：被**幽邃湾**咬出一个深约 18 格、口宽约 30 格的大凹湾（湾顶约 `(26,37)`），湾内是西北密林的水路腹地。
3. **东岸**：中段外凸（云栈翠屏余脉直逼海岸 `x≈105`），东北端伸出**风语海岬**（`(105,20)`），东南端伸出**残阳半岛**（`(100,68)`）。
4. **南岸**：平缓外凸的沙岸 `y ≈ 75~77`，东段被翠溪河口切开一个喇叭口，西段紧贴地牢断崖。

内陆另有 2 条横向/纵向脊线把大陆切成 **「北—中—南」×「西—中—东」** 的软性九宫（不是矩形，见 §2.2）。

### 1.4 三大标量场（生成器输入）

三个场在 `[0,1]`，由固定种子 fBm（5 阶，lacunarity 2.0，gain 0.5）生成：

```
h(x,y)  高程  = 0.55·fbm(x/48,y/48) + 0.30·fbm(x/18,y/18) + 0.15·fbm(x/6,y/6)
              然后与「山脊距离场」取 max：
              h = max(h, 1 - d_ridge / (band/2))     # d_ridge = 到最近脊线折线距离
w(x,y)  湿度  = 0.50·fbm(x/32,y/32) + 0.30·fbm(x/12,y/12) + 0.20·(1 - min(dist_water,8)/8) + 区域湿度偏置
t(x,y)  温度  = clamp(1.02 - y/64, 0, 1.05) + 0.05·fbm(x/24,y/24)
```

**地形分类（唯一真源，渲染/碰撞/植被共用）**：

| 层 | 判定 | 可通行 | 速度系数 | 渲染层 |
|---|---|:--:|---:|---|
| 深水 | `h < 0.30` 或海/河心 | ✗ | — | 深蓝 |
| 浅滩 | `0.30 ≤ h < 0.34` | ✓ | 0.55 | 浅蓝 + 岸线过渡 |
| 沙滩/泥滩 | `0.34 ≤ h < 0.36` | ✓ | 0.90 | 沙/泥 |
| 草地·平原 | `0.36 ≤ h < 0.62` | ✓ | 1.00 | 区域地面 |
| 丘陵 | `0.62 ≤ h < 0.74` | ✓ | 0.75 | 地面 + 山脚碎石 |
| 山地 | `0.74 ≤ h < 0.84` | ✓ | 0.55 | 岩石 + 雪盖（若达雪线） |
| **高岭** | `h ≥ 0.84` | ✗ | — | 裸岩/雪顶 |
| 岩浆 | 熔岩湖/赤涓 | ✗ | — | 发光橙红 |
| 外圈群山 | wall 区 | ✗ | — | 黑岩 |

**雪线**：`h ≥ 0.88 - 0.30·t` → 北境（`t≈0.85`）阈值 0.63，中部（`t≈0.42`）阈值 0.75，南部（`t≈0.05`）阈值 0.87。
另：凡 `t ≥ 0.78`（约 `y ≤ 15`）的地面强制覆雪（北境雪原），与高程无关。

### 2.2 边界如何「非矩形」

**废除 `regions[].rect` 作为几何来源**（保留字段仅用于兼容 UI/小地图取色）。区域归属改为**噪声扰动加权 Voronoi**：

```
region(x, y) = argmin_i  [ dist((x,y), C_i) × k_i × (1 + 0.30·fbm_i(x/22, y/22)) ]
```
- `C_i` = 上表中心；`k_i` = 面积权重（下表，值越小势力越大）
- 水域 / 不可通行高岭 **不参与区域归属**（`region = null`，渲染为水/岩色）
- 结果边界为自然曲线，且跨山系时自动沿山脚走

| id | 权重 `k_i` | 参考实测占比 |
|---|---:|---:|
| `nw_forest` | 0.84 | 11.6% |
| `n_snow` | 0.62 | 14.4% |
| `ne_pasture` | 0.98 | 8.9% |
| `w_waste` | 0.76 | 7.1% |
| `c_plain` | 0.78 | 18.4% |
| `east_ridge` | 0.92 | 11.3% |
| `sw_dungeon` | 0.86 | 7.3% |
| `s_desert` | 1.06 | 13.1% |
| `se_battle` | 1.06 | 7.8% |

> `w_waste`(7.1 vs 9) 与 `c_plain`(18.4 vs 20) 略低于目标，可调 `k` 到 `0.70 / 0.72` 修正；
> 工程实现时以 §9 判据 B2（各区落在目标 ±2%）为准做一次自动标定。

### 4.4 山如何「自然分隔」而不是矩形切断

1. **脊线是折线不是矩形**：M-1/M-3 用 7 / 5 个控制点，走向随地形摆动，宽度沿脊线在 `band ± 1.5` 间用 fBm 抖动。
2. **边界由高程场决定**：区域边界不是矩形，而是沿「山脚线」（`h = 0.62` 等高线）自然走，
   所以地图上看到的是"翻过这道山就换了天色"，而不是一条直线。
3. **每道主山系至少留 1 个主垭口 + 1~2 个次垭口**，保证不会因地形把 POI 封死（判据 E1）。
4. **山脚过渡带**：`h ∈ [0.62, 0.74]` 为可走丘陵，速度 0.75 —— 玩家能"蹭"过去但要付时间代价，
   形成软性阻隔而非硬墙。
5. **唯一硬封闭**是西南地牢（M-4 + M-5 + 海岸 + wall 围成马蹄形），只有 P-9 冥门一个口 —— 这是**有意为之**，
   用来给地狱道做「门」的仪式感（见 §6.5）。

### 6.4 探索节奏与「首次可达难度」梯度

1. **`realm_human` 故意做成最近（29 格）**。理由：人道 = 象棋 = `★ 主推`，README 明言主推；
   让主推内容成为玩家第一次出发就能找到的目标，符合「降低首次决策成本」。
   代价：与剧情第 4 顺位不一致 —— 但顺序本就不强制，且人道剧情不依赖前三条道。

探索的"路途感"更足，也让「上路 1.15×」的收益更可感知。需工程侧确认手感。

### 7.3 团簇算法（替代现有「每格独立哈希撒点」）

```
1. 泊松盘采样生成簇心：最小间距 D（表内 D 列），每区域独立种子
2. 每簇：半径 R，簇内密度 = 基础密度 × (1 - (d/R)^1.6)   # 中心密、边缘稀 → 自然林缘
3. 簇内再按「空地率」挖洞：对簇内每格取 hash(x,y,salt=簇id)，< 空地率 则跳过 → 林中空地
4. 多带叠加时取 max（不做加法），避免密度爆炸
5. 河岸带 V3 不走 1~3，直接沿水线做 1D 采样
```

> **关键**：现有 `decor_plant` 是「每格独立哈希」→ 视觉上是均匀噪点，没有"林"的感觉。
> 改成团簇后，密林会出现真正的林片 + 林中空地 + 稀疏林缘，读图质量提升最大，成本几乎不变（仍是预渲染期一次性）。

## 8. 探索体验设计

### 8.1 小地图可见性与迷雾

- **小地图底图**：仍然一次性按 `_minimapColor()` 烘 112×84（不变），但叠一层**迷雾遮罩**。
- **迷雾位图**：`112 × 84` bit，存 `localStorage['chesssage_ow_fog']`（与现有 `chesssage_ow_explored` 并存）。
- **揭示规则**：玩家每帧所在位置为心，半径 **14 格** 的圆形区域写入已探索（沿路走自然连成片）。
  另外：**道路具有"预揭示"** —— 玩家踏上某条道路后，整条道路沿线 2 格自动揭示（避免摸黑找路）。
- **未探索区**：小地图填 `#0d1117`（不显示地形色），主地图仍正常渲染（俯视视角不做视野遮挡，避免晕）。
- **POI 标记**：
  - 已探索过 → 显示对应 emoji。
  - 未探索 → **仅当玩家距该 POI ≤ 20 格 或 该 POI 所在道路已连通已探索路网**时才显示 `❓`；
    否则完全不显示（保留"发现感"，也避免开局就把九宫格全剧透）。
  - `realm_sandbox` 保持常驻直显（现有逻辑，不改）。

## 9. 验收判据（Acceptance Criteria）

> 共 **46 条**，分 A~H 八组。QA 用 `scripts/validate_overworld.py`（工程侧实现）读取
> `configs/overworld.json` 的烘焙数据逐条自动校验，输出 `validation_report.json`。
> 全部为**硬性**（除非标注「软性/建议」）。

### A. 几何与面积（6 条）

- **A1** 地图尺寸严格 `112 × 84`；`x ∈ [0,111]`，`y ∈ [0,83]`。
- **A2** `wallGrid` 恰为外圈 6 格：可通行区恰好是 `x ∈ [6,105]` ∧ `y ∈ [6,77]`（= 7200 格）。
- **A3** 可通行陆地（非 wall、非深水、非高岭、非岩浆）占**内陆 7200 格**的 **55%~65%**。
- **A4** 深水（海 + 河 + 湖心）占内陆 **14%~24%**。
- **A5** 不可通行高岭（`h ≥ 0.84`）占内陆 **10%~18%**，且 ≥ 90% 落在 §4.1 的七条脊线带内。
- **A6** 湖泊总面积 **160 ~ 260 格**；镜湖为最大湖且面积 ≥ 50 格。

### B. 区域（5 条）

- **B1** 九个 `regions[].id` 全部存在且与本文 §2.1 一致；`rect` 字段保留但**不参与几何生成**。
- **B2** 九个区域的格数占比全部落在 §2.1「面积占比目标」的 **±2 个百分点**内。
- **B3** 任意两个相邻区域之间存在**长度 ≥ 12 格的连续非矩形边界**（检测：边界线段的走向变化 ≥ 3 次 / 每 12 格）。
- **B4** 不存在"矩形直边"：任一区域边界中，直线段长度 > 20 格且完全平行于 x/y 轴的段数 = **0**。
- **B5** 每个区域的中心 3 格内，地形（高程带/湿度带）落在 §2.1 声明的区间内。

### C. 水文（7 条）

- **C1** 五条河（R-1 ~ R-5）均存在，且每条 ≥ 5 个控制点（R-5 为 4 个，允许）。
- **C2** 每条河的宽度沿程**单调不减**（上游 ≤ 中游 ≤ 下游），且下游最大宽度 ≥ 上游 + 2。
- **C3** 每条河从源到终点**连续**（4 邻接连通），中途不出现宽度为 0 的断裂（R-5 断流段除外）。
- **C4** 每条河的入海口/终点确实与「海」或「目标湖」相接（终点 2 格内存在水格）。
- **C5** **无 1 格孤岛水洼**：不存在面积 = 1 格的水体连通块；面积 ≤ 3 格的水洼总数 = **0**（填平或并入）。
- **C6** 六个湖泊的位置/半径与 §3.3 一致（中心偏差 ≤ 2 格），水深分层齐全（浅/中/深或注明全浅/全深）。
- **C7** 融雪河确实**穿过镜湖**（镜湖内存在 ≥ 4 格河-湖重叠格）；翠溪确实发源于云栈天池。

### D. 山系与通行（5 条）

- **D1** 七条脊线存在，且各脊线 90% 以上的核心格 `h ≥ 0.84`（不可通行）。
- **D2** 九个垭口（P-1 ~ P-9）全部**可通行**（垭口中心 3×3 内 `h < 0.74`），通道宽度与 §4.3 一致 ±1。
- **D3** 雪线规则生效：`n_snow` 区域 `y ≤ 18` 的地面覆雪率 ≥ 95%；`sw_dungeon` 与 M-4/M-5 覆雪率 = **0%**。
- **D4** 山脚碎石带存在（脊线外 2 格内碎石装饰密度 ≥ 0.15），且碎石**全部非阻挡**。
- **D5** 全部 7 座桥/渡口的桥面格 `flag & ROAD` 为真、`flag & WATER` 为假，桥两端 2 格内均有可走陆地。

### E. 路网与可达性（8 条）

- **E1** 从 `spawn (58,45)` 出发，在「不可走 = 深水 + 高岭 + 岩浆 + wall + solid_regions」规则下，
  **4 邻接 BFS 可达**全部 11 个 POI（含 6 道入口 + 菩提老者 + 沙盒 + 告示牌 + 成就殿堂 + 生灭台自身）。
- **E2** 每个 POI 距最近道路格 ≤ **3 格**。
- **E3** 每条道路的**所有**路面格都不落在深水 / 高岭 / wall 上（垭口与桥面除外，二者须显式白名单）。
- **E4** 可通行陆地中**不存在面积 < 8 格的孤立连通块**。
- **E5** 删除任一条**次级道**（R5~R12）后，E1 仍成立。
- **E6** 删除任一条**主干道**（R0~R4）后，E1 **不**成立（证明主干道确为咽喉）。
- **E7** 生灭台到六道入口的沿路格数落在 §6.4 表格的 **±15%** 内。
- **E8** 道路总长度 ≤ 全图格数的 **18%**（≤ 1693 格），避免"到处都是路"。

### F. POI（7 条）

- **F1** 11 个 POI 的 `id` 与 `realm` 键名与 `configs/overworld.json` **完全一致**（不可增删改名）。
- **F2** 每个 POI 所在格**可通行**，且**不在水中、不在山体上、不在 wall 内**。
- **F3** 每个 POI 到最近**水格**的欧氏距离 ≥ **3 格**。
- **F4** 每个 POI 到最近**不可通行高岭**的欧氏距离 ≥ **3 格**。
- **F5** 每个 POI 半径 **5 格内**至少有 **1 个**该 POI 专属 `decor_anchors` 组（每组 4~6 个锚点）。
- **F6** 六个 realm POI 分别落在其声明的区域内（`realm_human → s_desert` 等，见 §6.1）。
- **F7** 六个 realm POI 两两之间的最小曼哈顿距离 ≥ **30 格**（避免挤在一起）。

### G. 植被与装饰（4 条）

- **G1** 植被分布**不再**是每格独立哈希：在 `nw_forest` 内做团簇检测，
  相邻格密度的空间自相关（Moran's I）≥ **0.25**（纯随机会接近 0）。
- **G2** 每个植被带的实测密度落在 §7.2 声明区间的 **±0.03** 内（V6 荒漠为 ±0.01）。
- **G3** 道路格与距路 1 格内的植被密度 ≤ 该带基础密度 × **0.25**。
- **G4** 全部 solid 装饰物不阻断 E1 的可达性（把 solid 加入阻挡集后重跑 BFS，结果不变）。

### H. 数据与确定性（4 条）

- **H1** 生成器以 `seed = 20260828` 连续运行 **2 次**，输出 `configs/overworld.json` 的**逐字节一致**。
- **H2** 输出保留 `world / regions / pois / roads / player` 五个字段（兼容 UI 与小地图）。
- **H3** `_minimapColor()` 的九个区域取色键不变；新增地形（水/山/路）的颜色由烘焙 `tiles_color` 数组提供。
- **H4** 生成耗时 ≤ **15 秒**；烘焙数据体积 ≤ **3 MB**（JSON，含 112×84 的 `h/w/t/flag/road/region` 六层）。

### 9.1 生成器标定提示

- **海平面 `S`**：`h < S` 判为水。用二分法求解 `S`，使判据 A3 落在 **60%**（区间中值）。
- **区域权重 `k_i`**：若某区偏离 B2，按 `k_i ← k_i × (实测占比 / 目标占比)^0.5` 迭代 ≤ 5 次。
- **垭口白名单**：E3 校验时把 §4.3 的 9 个垭口中心 ±(通道宽/2) 与 §3.4 的 7 座桥面格加入白名单。
