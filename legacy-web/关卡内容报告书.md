## 八、关卡难度曲线说明

### 8.1 难度参数维度

每个关卡的难度由以下参数共同决定：

| 参数 | 含义 | 取值范围 |
|:-----|:-----|:---------|
| `difficulty` | 关卡难度系数 | 1-5（1 最易，5 最难） |
| `ai_personality` | AI 行为风格 | normal / aggressive / defensive / hard / aggressive_random / defensive_hard |
| `ai_depth` | Minimax 搜索深度 | 2-4（2 浅，4 深） |
| `turn_limit` | 回合限制 | 20（多数）/ 40（围棋） |
| `objective` | 胜利条件类型 | checkmate / capture_count / turn_limit / evacuation / board_coverage / color_coverage / formation / survival / assassination / escort / compound |
| `type` | 关卡类型 | standard / puzzle / objective / boss |

### 8.3 难度递进规律

#### 8.3.1 单道内难度递进

每道 5-6 关，难度从 1 递增至 4-5：

| 关卡序号 | 典型难度 | 典型类型 | 典型 AI |
|:--------:|:--------:|:--------:|:--------|
| 第 1 关 | 1 | standard | normal, depth=2（教学难度） |
| 第 2 关 | 2 | standard | normal, depth=3（基础难度） |
| 第 3 关 | 3 | standard | aggressive, depth=3（进阶难度，含小选择） |
| 第 4 关 | 3-4 | puzzle/objective | normal, depth=3（特殊目标考验） |
| 第 5/6 关 | 4-5 | boss | 极致 ai_personality, depth=4（Boss 战） |

#### 8.3.2 跨道难度递进

六道之间难度递增，但每道第 1 关都会"重置"到较低难度给玩家喘息：

| 道 | 第 1 关难度 | 第 3 关难度 | Boss 难度 | 总难度趋势 |
|:--:|:----------:|:----------:|:---------:|:----------|
| 地狱道 | 1 | 3 | 4 | 起步 |
| 饿鬼道 | 1 | 3 | 4 | 起步（同难度，新机制） |
| 畜生道 | 1 | 3 | 4 | 起步（同难度，新机制） |
| 人道 | 1 | 3 | **5** | 抬升（Boss 难度 5，hard AI） |
| 阿修罗道 | 1 | 3 | **5** | 抬升（Boss 难度 5，aggressive_random） |
| 天道 | 1 | 3 | **5** | 抬升（Boss 难度 5，defensive_hard） |

**设计意图**：每道第 1 关都给玩家"重新开始"的喘息空间；Boss 难度从第 4 道开始抬升至 5，与剧情节奏同步——后三道对应主角更深层的人格（理性、愤怒、真我），需要玩家投入更多策略。

### 8.4 关卡类型分布

| 关卡类型 | 数量 | 占比 | 出现位置 |
|:--------|:----:|:----:|:--------|
| standard | 18 | 55% | 每道第 1-3 关 |

### 8.5 胜利条件分布

| 胜利条件 | 使用次数 | 使用关卡 |
|:--------|:--------:|:--------|
| checkmate | 21 | 多数 standard + 所有 boss |
| capture_count | 2 | hell_4（target=15）, human_5（target=4） |

**设计意图**：`checkmate` 占多数保证基础体验稳定；其余 10 种胜利条件分散在 puzzle/objective 关，提供多样性。`evacuation`、`escort`、`formation`、`board_coverage`、`compound` 等类型在 `objective_types.json` 已定义但当前关卡未使用，预留给后续扩展。

### 8.6 特殊奖励关卡

| heaven_5（天光） | -30 | 完成 80% 颜色覆盖率 |

**设计意图**：奖励玩家追求高难度目标，缓解后续 Boss 战的业力压力。

| **关卡触发** | 进入关卡/关卡结束时 | `opening` / `ending` | 自动播放对话框 |
| **回合触发** | 特定回合数（如第 3、5、10 回合） | `mid_events[].trigger = "turn_N"` | StoryManager 监听 current_turn |
| **业力触发** | 业力高于/低于阈值 | `mid_events[].trigger = "karma_high"`, `threshold` | StoryManager 监听 level_karma |
| **事件触发** | 吃子/将军/作弊/翻转等游戏事件 | `mid_events[].trigger = "event_name"` | 各棋类 `_trigger_karma_recover` 钩子 |
| **选择触发** | 玩家做出选择后 | `choices[].effect` | 选择界面 → 后端同步 → 后续剧情 |

### 9.2 剧情注入位置总览

| 位置 | 触发时机 | 内容 | 形式 |
|:----|:--------|:-----|:-----|
| **道开场** | 进入新的一道时（每道第 1 关 opening） | 道背景介绍、守道者初登场 | 全屏过场动画 + 对话 |
| **关卡开场** | 每关开始前（opening 字段） | 本关剧情铺垫、目标说明 | 对话框 + 角色立绘 |
| **局内事件** | 特定回合/事件触发（mid_events 字段） | 角色内心独白、守道者对话 | 浮窗对话 + 音效 |
| **关卡结束** | 关卡胜利/失败后（ending 字段） | 剧情进展、人物反应 | 对话框 + 角色表情变化 |
| **道通关** | 击败守道者后（Boss 关 ending + choices） | 道总结、关键选择、下一道预告 | 过场动画 + 选择界面 |
| **记忆碎片** | 满足"全程无作弊通关"等条件（每道 Boss 关后判定） | 主角过往回忆、人格成因 | 全屏 CG + 旁白 |
| **结局** | 通关天道后（heaven_6 Boss 关 ending） | 最终结局、片尾 | 全屏动画 + 制作人员名单 |

### 9.8 剧情数据结构

剧情数据集中在 `configs/story.json`（v1.4，剧情与资产映射权威源）。

**字段结构以实际文件为准**：`configs/story.json` 顶层为 `version` / `_meta` / `protagonist` / `guide` / `realms`（对象，按道键索引，`levels` 为按 `"1".."N"` 键索引的对象）/ `prayers` / `endings` / `tiandao` / `detection`（识破判词 judgment_text / reset_message）/ `real_world_characters` / `prologue` 等。每关用 `dialogues`（对白数组，对象含 `speaker` / `portrait` / `text`）；Boss 关用 `dialogues_before` + `dialogues_after`；道守道者字段为 `guardian`（其 `name` 为剧情权威源，`bosses.py` 读取覆盖机械配置中的同名）；选择字段为 `choices`（数组，每项含 `index` / `prompt` / `options`）；记忆碎片字段为 `memory_fragment`（含 `condition` / `narration` / `cg` / `cg_video`）。

**权威 schema 说明**：完整字段定义、资产映射（`cg_video` / `animation` 等）与示例 JSON 见 [轻RPG化剧情实现草案_v1.4.md §7.1](轻RPG化剧情实现草案_v1.4.md) 与 [RPG化执行方案_v1.1.md §7](RPG化执行方案_v1.1.md)。`configs/tiandao_boss.json` 仅保留机械配置（棋子/规则/AI/胜负条件），其对话已合并到 `story.json.tiandao.boss_dialogues`。

### 9.9 实现方式

- 在每个棋类前端 `static/app.js` 中增加 `StoryManager` 模块（Web Component）
- 监听游戏事件（回合变化、业力变化、胜负、吃子类型等）
- 匹配 `configs/story.json` 中的触发条件，播放对应剧情
- 与 samsara 后端同步剧情进度（选择、记忆碎片、悟道/堕落值）
- 通过已挂载的 `/assets` 静态路由加载角色立绘与背景图
