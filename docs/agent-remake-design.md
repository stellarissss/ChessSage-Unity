```
T_eff = 全轮 prompt + completion token 累计（含 thinking token）
karma = clamp(round(f(T_eff) × 波动因子), 1, single_max = 120)
f 为凸函数（小改便宜、大改超线性）

超 single_max 早停；预览实时显示「已耗 X token，业力 Y 且仍在增长」
```

## 1. 业力-Token 手感校准（核心）

### 1.1 新定价链路一览

```
玩家输入一句话
   │
   ▼
┌──────────────── Agent 推演（进程内 MCP）────────────────┐
│ 每轮：prompt(系统提示+工具schema+历史) + completion(thinking+工具调用) │
│ 每轮结束 → 回调 usage → T_eff 累计 → UI 实时刷新               │
│ 轨迹事件流：「天道阖目推演…（+620 token）」                       │
└────────────────────────────────────────────────────────────┘
   │
   ▼ f(T_eff) × 波动因子 → clamp(1, 120)
   ▼
预览（diff 卡 + 代价卡 + 推演摘要）→ 玩家确认 → IncreaseKarma →（溢出则识破结算）
```

与旧链路的本质差别：**旧价目表估计"这一手有多大"（分类×强度×局势，评估过程对玩家不可见）；新价目表计量"天道为此忙了多久"（token，实时可见）。**

### 1.2 为什么「小改便宜、大改超线性」与旧价目表心理等价

**旧价目表的心理契约**（引自 `KarmaEstimator` prompt 与 `legacy-web/hub/tutorial-content.js` 玩家可见文案）：

| 旧分类 | 玩家感知的"妄念大小" | 旧业力 |
|:--|:--|:--:|
| E 闲聊/查询 | "搭句话，不动棋" | 1（固定） |
| D 界面/外观 | "最轻的改动：换个颜色" | 8–23 |
| B 棋盘/棋子位置 | "动一动棋子" | 23–53 |
| A 机制修改 | "动一动回合/对手" | 30–60 |
| C 规则/走法 | "动天规本体" | 45–90 |
| C+ 创建新棋子 | "无中生有" | 75–120 |

旧体系的"超线性"实际来自三处，在新体系中全部有对应物：

| 旧机制 | 新对应物 | 等价性论证 |
|:--|:--|:--|
| **档位跳档**（E=1 → C+=97，跨两个数量级） | f 的**边际递增**：每千 token 的边际业价从 0.0027 涨到 0.0072（+164%，见 §1.5 斜率表）。小改落在膝点前的"平地价区"，大改自动进入加速区 | 玩家体感同为"越往后越贵" |
| **强度倍数 ×1/×2/×3**（改 1/2/3 个目标） | token 自然复现：一次改 3 条规则 = 3 倍补丁内容 + 1-2 个额外校验轮次 + 更长 thinking。**不需要人工判断"改了几个"，token 自己会算账** | 多目标请求在新体系下同样超线性；偏差方向见 §1.4 注 |
| **检测公式 O^1.5**（溢出部分非线性） | **原样保留**（`KarmaEstimator.CalculateDetectionDelta` 逻辑迁入 Samsara 侧不动） | 完全一致 |
| **局势调整 ×1.2/×0.9** | 无对应物（token 不关心棋盘局势） | 见 §5 决策点 D-5，默认关闭 |

**逐档对应分析**（旧分类 → 新 token 预算 → 目标业力，详见 §1.4 锚点表）：

- **E=1「搭话不要钱」**：零工具闲聊 1 轮 ≈ 2,500 token，落在平地价区（f=1）；按零写入统一语义（§1.4.1）**恒收 1 点**——旧"闲聊基本免费"的 affordance 完整保留（决策点 D-1）。
- **D 最轻**：只读 `ui_config`（≈130 token 的最小配置），全链路最轻的修改 → 8,000 token → 16 点（旧中位 15，+6.7%）。"外观最便宜"的直觉保留。
- **B 动棋盘**：读 `board_state`（≈1,200 token）+ 移子补丁 → 12,000 token → 32 点（旧中位 38，−15.8%）。
- **A 动机制**：机制挂在 `board_state.mechanisms` 下，比 B 多半轮确认 → 15,000 token → 48 点（旧中位 45，+6.7%）。
- **C 动天规**：读 `pieces_*` + `rules` + 生成走法补丁 + 校验 → 16,000 token → 55 点（旧示例"把我的马变成炮"=53，+3.8%）。
- **C+ 无中生有**：读全量配置 + 构造完整新子定义 + 校验 + 大概率一次重试 → 21,000 token → 91 点（旧中位 97，−6.2%；波动+激增后顶格 120，与旧 C+ 上沿重合）。

**结论**：两套价目表说的是同一门直觉语言——"为多大的妄念付多大的业价"。差异只在两处，且都是任务书允许的：**计价器从暗处搬到明处**（隐藏 LLM 评估 → 实时 token 表），以及**误差方向**（小改略便宜 −16%、大改略贵 +7% 以内），后者正是"局部偏差以增加刺激性"——它奖励"把话说准"的新技巧（§4.2）。

### 1.3 Token 预算模型（每轮成本）

单模型（DeepSeek v4.1 flash，thinking 默认开启且计费），Agent 每轮成本：

```
prompt_r    = S + C_cmd + 历史(往轮 completion + 工具结果回执)
completion_r = thinking_r + 工具调用JSON_r（或最终答复_r）
```

| 成本项 | 估值（token） | 说明 |
|:--|:--:|:--|
| S 系统提示+工具 schema | ≈1,500 | 天道人设 ≈300 + 9 个工具的紧凑 schema ≈1,200。**工程必须压到这个量级**，否则每轮固定成本吃掉全部校准（见 §6） |
| C_cmd 玩家指令 | 30–60 | |
| 工具结果（原始） | `board_state` ≈1,200；`pieces_*` ≈360/侧；`rules` ≈324；`ui_config` ≈130 | **阅后即焚**：工具结果进入历史后，由宿主压缩为 ≈100 token 的回执（"天道瞥一眼便记住，不必每次都摊开全文"）——这是叙事原生的上下文治理，也是校准成立的关键工程约定 |
| thinking_r | 400–1,500/轮 | 计费。歧义请求更长 |
| 工具调用 JSON | 100–400/轮 | |
| 校验失败回执 | ≈150/轮 | 触发重试轮 |

任务形态 → 轮次 → T_eff 区间（P10–P90，锚点取中位）：

| 形态 | 典型轮次 | T_eff 区间 | 锚点 |
|:--|:--:|:--:|:--:|
| E 闲聊（零工具） | 1 | 2,000–3,000 | 2,500 |
| D 外观（读 ui_config→补丁→确认） | 2–3 | 6,500–9,500 | 8,000 |
| B 移子（读 board_state→补丁→确认） | 3 | 10,000–14,000 | 12,000 |
| A 机制（读 board_state→机制补丁→确认） | 3–4 | 13,000–16,000 | 15,000 |
| C 改规（读 pieces+rules→补丁→校验→确认） | 4 | 14,000–18,000 | 16,000 |
| C+ 铸子（读全量→构造→校验→重试→确认） | 5–6 | 19,000–24,000 | 21,000 |

> 以上为**模型估算**，必须在集成后用真实 DeepSeek v4.1 flash 用量回归校准（§6.4 校准试玩）；且校准必须在**生产速度配置**（§6.4 第 0 步）下跑——压缩思考会降低 T_eff、业力落点随之下移。锚点全部参数化，重拟合不改代码。

### 1.4.1 零写入（E 档）统一业力语义（QA R4 定稿，2026-10-23）

**统一规则**：一次 Agent 运行**成功收敛且沙箱零写入**（纯闲聊、答妄问、只读查询——没有任何写工具成功调用）→ 业力**恒 1 点**，不经过 f(T_eff)、不随 σ/surge 浮动。

**工程可执行判定**（与工程侧 §7.1 已同口径实现，QA 探针可写死断言）：

```
成功收敛路径（进入计价）：
  writes == 0   → karma = 1                          // 恒 1，不走 f、不走 roll
  writes > 0    → clamp(round(f(T_eff) × σ × surge × discount) + flat, 1, single_max)
失败路径（不进入计价）：
  失败卡，不收费（两段式契约：无预览不扣费）
```

- `writes` = 沙箱写入数（写工具成功调用计数，工程侧遥测字段 §13.7）；读工具（`inspect_board`/`read_rules`）与答妄问不计写入。
- 与失败路径的边界：零写入但**未成功收敛**（20s 到点无产出 / 收手无补丁 / 校验错误耗尽 / Agent 拒绝）→ 失败卡 **0 点**。即 E 档的 1 点只付给"天道答上了话"的运行。

**为什么恒 1 而不是 cap 5**（决策点 D-1 口径定稿）：

1. **affordance 完整继承**：旧 E 类原文即"固定 1"，恒 1 是同一条规则的最简形态；cap 5 只是同一 affordance 的更松表述，却多引入一个参数和一个边界（"多长算长"）。
2. **无平衡敞口**：闲聊/只读不产生任何游戏状态变化，业力定价在此处只承担"搭话不要钱"的心理功能，不承担成本控制——API 成本由 20s 硬顶 / 4 轮上限 / 60k 保险丝控制（工程侧 §13.1）。
3. **一句话教程**："不动棋，就 1 点。"（§6.5 教程同步项）。
4. **QA 可写死断言**：成功零写入 → `karma == 1`（64 seed 全扫描恒 1）。QA 夹具 E 档区间 [1,5]（KRM-07）在恒 1 下自然满足（1 ∈ [1,5]），**夹具无需改动**；`chat_cap=5` 降级为**保险丝参数**——语义为"零写入路径业力硬上限"，恒 1 规则下默认不触发，仅当未来启用"长对话按 token 计费"变体时防止爆米。

**边界情形裁决**（回答工程侧 §12.1-3 的提问）："玩家让 Agent 查了 10 次棋盘但零修改" → 收 1 点，与闲聊同价（只读无游戏状态变化；且阅后即焚回执下 10 次读取的 T_eff 已被压缩，§1.3）。

### 1.5 凸性验证与"超线性"体感

| 区段 | token 区间 | 边际业价（点/千 token） |
|:--|:--:|:--:|
| 平地价区（搭话/微调） | 0–2,500 | 0（f=1） |
| 膝点爬升 | 2,500–8,000 | 2.7 |
| 常规改规 | 8,000–12,000 | 4.0 |
| 机制/改规加速 | 12,000–15,000 | 5.3 |
| 改规深水区 | 15,000–16,000 | 7.0 |
| C+ 铸子区 | 16,000–21,000 | 7.2 |

- **凸性**：边际业价单调非降（0 → 2.7 → 4.0 → 5.3 → 7.0 → 7.2），f 为凸函数，证毕。
- **体感来源**：玩家在实时计数器上直接看到"业价攀升加速"——同样 1,000 token，在 D 档值 2.7 点，在 C+ 档值 7.2 点。**"想得越久，业力越贵"不是文案，是屏幕上的斜率。**
- **触顶点**：f=120（单次上限）落在 T_eff ≈ 25,000 token。解读口径（写进教程）：**"天道容得下大约两万五千 token 的推演；再多，业价顶格，天机将断。"** 技能抬高上限后：单次上限 150 → ≈29.2k；160 → ≈30.6k（与 `karma_capacity_t2a` / `cheat_mastery_t3b` 天然联动）。

### 1.6 波动机制设计：混合制（均匀 + 阈值激增）

三个候选的心理分析：

| 方案 | 机制 | 不确定性 | 赌博感 | 可控感 | 判定 |
|:--|:--|:--:|:--:|:--:|:--:|
| 纯均匀 0.8–1.3 | 每手都 ±30% | 高但均匀 | 均匀分布，快速脱敏 | 高（可按区间预算） | ❌ 刺激衰减快 |
| 纯阈值激增 | 小平价稳定，大额概率暴涨 | 低档无、高档炸 | 戏剧性强 | **低**——暴涨在结算才揭晓，玩家无法干预，违背"玩家掌舵" | ❌ |
| **混合（推荐）** | 均匀保底 + T≥20,000 时 30% 概率 ×1.25–1.5 | 高 | 高低档皆有，高档有峰值 | **高**——实时计数器让玩家在逼近阈值时主动选择"收手"还是"赌一把" | ✅ |

**推荐参数**（默认值，全部可配）：

```
uniform:     U(0.8, 1.3)
surge:       T_eff ≥ 20,000 时，p = 0.30，因子 ∈ U(1.25, 1.5)
chat_cap:    5（零写入路径业力硬上限·保险丝；恒 1 规则下不触发，见 §1.4.1）
seed:        每请求一个种子（会话种子 + 请求序号），可复现（QA 回放）
```

**设计意图**：
1. 均匀分量保证"同一手每次价钱不同"——玩家无法背诵价目表，预览数字始终有意义；旧体系里同一指令因 LLM 评估噪声也有浮动，这一条是等价继承。
2. 激增分量把戏剧峰值放在**高赌注区**（C+ 及多改请求），且因为实时计数器先行报警（§1.7），激增从"暗算"变成"明示后的抉择"——球在玩家手里，只是球面不规则。
3. 激增后 clamp 到 120：C+ 的实际上限 = 91×1.375 ≈ 125 → 顶格 120，与旧 C+ 上沿（120）重合。
4. 波动的世界观包装（预览时揭晓）：≤0.9「天道今日心善」；0.9–1.1「天机如常」；1.1–1.3「天道眼神意味深长」；激增「天机浊气暴涌——此番推演，价重三分！」

### 1.7 早停 UX：实时计数器与「收手」

**展示内容**（处理中遮罩卡，替换现有"阶段：意图解析/规则生成"单行文本）：

```
┌────────── ☯ 天机推演 ──────────────────────────────┐
│  ◐ 天道阖目，暗自推演你这一手的因果……              │
│  ───────────────────────────────────────────────   │
│  已耗 14,820 token（思索 6,200 · 改数 8,620）      │
│  业力预估 48 · 仍在增长…                            │
│  [ ⏱ 18.4s ]              [ ✋ 收 手（Esc） ]      │
└────────────────────────────────────────────────────┘
```

**刷新节奏**：
- **P0 分步刷新**：每个 Agent 轮次结束（usage 回调）刷新一次——计数器、token 拆分（思索=completion / 改数=prompt）、业力预估（f(T_partial)，标注"预估·未含天意浮动"）。轮内 thinking 期间显示脉动动画 + "阖目推演……"。
- **P2 流式刷新**（可选）：`LlmClient` 开 `stream=true`，按 chunk 累计 token，计数器连续跳动——沉浸感更强，但实现成本高，且分步刷新已满足"实时"验收标准。**建议 P0 分步、P2 评估。**

**软提示阶梯（SoftHint，按 20s 总预算重排——2026-10-23 裁决 #4）**：

| 时刻 | 触发 | 表现 |
|:--:|:--|:--|
| t=0 | 提交受理 | 遮罩 + 轨迹首条「你的妄念，天道听见了。」+ 脉动动画；「收手」按钮常驻可点 |
| t=3s | 首字未达（TTFT 超标） | SoftHint-1「天道推演中……」+ token 计数器就位（0 起跳，轮级刷新） |
| t=6s | 仍在运行 | SoftHint-2「天道阖目，暗自推演你这一手的因果……」+ 四段进度条（按 MaxRounds=4 预算映射，每轮一段） |
| t=12s | 超过 P50 目标线 | SoftHint-3「推演颇深，业价渐升——想收手，还来得及。」（计数器已转红则省略） |
| t=16s | 逼近硬顶 | SoftHint-4「天机将断——天道至多再推 4 秒；再深，也是业价顶格。」 |
| t=20s | 到点 | 收尾策略 A（§3.5）：有写入 → partial 预览；无写入 → 失败卡 |

> **旧 8s 单发软提示废止**：生产预算 P50 ≤12s / P90 ≤18s（工程 §13.1）意味着多数正常请求在 8s 时仍在健康推进——单发软提示会在多数请求上误触发，把"正常速度"暗示成"系统慢了"，反灌等待焦虑。阶梯只在尾部出现，且每级都带**可行动信息**（进度段位 / 收手提示 / 将断预警），不是单纯安抚。软提示是纯 UI 侧计时器：零工程成本、不动 API 流；P0 轮级刷新即可支撑，P1 流式让计数器连续跳动（工程 §13.5）。

**危险预测**（早停的决策核心）：
- f(T_partial) ≥ 100，或按当前轮均成本外推将越过 f=120（T≈25,000）时：计数器转琥珀→红，追加 `⚠️ 再推下去，业力将触顶 120——天道不容。建议收手。`
- **这是全游戏最重要的 agency 时刻**：旧体系在评估超标后**事后拦截**（玩家干等 20 秒然后被拒）；新体系让玩家**看见火车驶来并有权跳车**。

**「收手」语义**（Esc 等效）：

| 时机 | 结果 | 收费 |
|:--|:--|:--:|
| Agent 已走完（完整补丁校验通过） | 直接进预览（等同正常运行结束），按 f(T_eff) 计价 | 确认才收（两段式契约不变） |
| Agent 有写入但未走完（部分补丁落地） | partial 预览，banner「你及时收手，天道推演半途而止——所得几何，造化自负。」，按 f(T_stop) 计价（§3.5） | 确认才收 |
| Agent 尚未产出补丁（零写入） | 失败卡「你及时收手，天道推演半途而废。妄念已散，不耗业力。」 | **不收**（契约：无预览不收费；真实 API 成本作为"收手权"的代价接受） |
| 收手后取消预览 | 回输入态 | 不收（沿用 UX-CHEAT-001 §5.3 取消不扣费，E3 测试不变） |

**系统侧保险**（玩家没收手时的底线，生产配置=工程 §13.1）：轮次上限 **4**（生产值；8 为校准/调试参数，不进生产配置）、token 硬停 60,000（API 成本保险丝；延迟预算先于它绑定）、**产品级硬超时 20s**（UI 既有值；裁决 #4：20s 是玩家体验底线，每次任务不得高于 20s，越快越好——**本设计不因等待焦虑放宽超时**，对冲手段是工程提速 + 软提示阶梯 + 收手权 + 轨迹动画）。

**提前终止的统一收尾（收尾策略 A）**：轮次耗尽 / token 硬停 / 20s 到点 / 连续工具错误 ≥3 —— 任一触发**不再默认失败卡**，一律走策略 A：**有写入 → 半成品预览按 f(T_stop) 计价；无写入 → 失败卡不收费**（UX 定稿见 §3.5）。与裁决 #3 同哲学：天道按实耗记账、不预判、不滥罚。

## 2. 技能门控换轴

### 2.1 旧机制删除清单

`GetAllowedClassifications`（E/F/A/B/C 恒可用；C+ 需 `cheat_mastery_t1a`；D 需 `cheat_mastery_t1b`）随分类体系一并删除。技能树**必须保留**（技能点经济、成长曲线、UI 都已上线），要换的是**门控的语义轴**。

### 2.2 三个候选轴

| 轴 | 机制 | 优点 | 缺点 | 判定 |
|:--|:--|:--|:--|:--:|
| A 业力档位 | 按当前业力/道行解锁能力 | 读数现成 | **反向激励**：业力低时反而不能作弊；与技能点经济脱钩；业力是消耗品不是成长 | ❌ |
| **B 工具层级** | MCP 工具清单按技能解锁过滤（server-side） | 1:1 替换旧门控；技能点经济不变；工具名即人话，可读性最好；旧分类→工具有自然映射 | 需维护"技能→工具"映射表 | ✅ **推荐** |
| C 累计 token / 天道声望 | 按历史消耗解锁 | 新颖 | 奖励刷量（刷闲聊也涨 token）；无持久化字段；叙事自相矛盾（天道该因你求得多而**更提防**，而非给得多） | ❌（可作 P2 装饰性头衔"天命成就"，不作门控） |

### 2.3 推荐方案：工具层级门控（"天机型谱"）

**MCP 工具清单草案**（进程内工具主机；门控在**工具 schema 下发给 Agent 之前**过滤——Agent 根本看不到未解锁的工具，既不浪费 token 试探，也不泄露"存在但锁着"）：

| 工具 | 天道行话 | 门控 | 旧对应分类 |
|:--|:--|:--|:--|
| `inspect_board` | 览局 | 恒可用 | B（读） |
| `read_rules` | 阅卷 | 恒可用 | B/C（读） |
| `patch_piece_moves` | 改走法 | 恒可用 | C |
| `move_piece` | 移子 | 恒可用 | B |
| `patch_mechanism` | 改机制 | 恒可用 | A |
| `answer_question` | 答妄问 | 恒可用 | E |
| `alter_win_conditions` | 改胜条 | 技能：高级规则（`cheat_mastery_t2b`） | A2/C 核心 |
| `create_custom_piece` | 铸新子 | 技能：自定义棋子（`cheat_mastery_t1a`） | C+ |
| `modify_ui_config` | 改容颜 | 技能：前端修改（`cheat_mastery_t1b`） | D（含 D2 多区段） |

旧 F 类（引擎级修改）**没有对应工具**——Agent 遇到这类请求只能"拂袖"拒绝（§3.4 边界案例），与旧体系"通常不可行"一致。

### 2.4 对现有技能树数值与文案的影响

`skill_tree.json` 四分支 12+ 节点中，只有 `cheat_mastery` 分支的门控语义需要改写，其余（业力掌控/隐匿之术/六道悟道）操作的都是业力与识破数值，**原样保留**：

| 技能 | 旧效果 | 新效果 | 文案改写 |
|:--|:--|:--|:--|
| `cheat_mastery_t1a` 自定义棋子 | 允许 C+ 类作弊 | 解锁工具 `create_custom_piece`（铸新子） | 「解锁天机型谱·铸新子：可请天道无中生有，造一枚新棋子」 |
| `cheat_mastery_t1b` 前端修改 | 允许 D 类作弊 | 解锁工具 `modify_ui_config`（改容颜） | 「解锁天机型谱·改容颜：可改动棋子外观与界面（含多区段齐改）」 |
| `cheat_mastery_t2a` 效率欺诈 | AI 评估有 30% 概率降 1 档 | **波动区间收紧**：roll 上限 1.3→1.15、下限 0.8→0.85（"天道推演有时会手下留情"） | 「神思省力：天价浮动区间收窄（0.85–1.15），不再大起大落」 |
| `cheat_mastery_t2b` 高级规则 | 允许修改胜利条件/核心规则 | 解锁工具 `alter_win_conditions`（改胜条） | 「解锁天机型谱·改胜条：可改写胜利条件与核心规则」 |
| `cheat_mastery_t3a` 白嫖 | 每局 1 次不消耗业力 | **不变** | 不变 |
| `cheat_mastery_t3b` 深层作弊 | 单次上限 +40 | **不变**（token 体系下=可推演到 ≈30.6k token） | 「天道容忍上限 +40（可推演更深，业价顶格更晚到来）」 |
| 其余 9 节点 | — | 不变 | 不变 |

**数值影响结论**：单次上限类技能（t2a 上限+30 / t3b +40）在 token 体系下反而更重要——它们直接把"天道容忍的 token 量"从 25k 抬到 30k+，是 C+ 流派的硬前置。`efficiency_fraud` 从"降档"改为"收紧波动"，保留原技能的随机 flavor。

### 2.5 玩家学习成本分析

| | 旧体系 | 新体系 |
|:--|:--|:--|
| 要学什么 | 七分类 taxonomy（A/B/C/C+/D/D2/E/F）+ 强度倍数 + 局势调整，且**对局中不可见**（只有事后一行小字） | 无 taxonomy；技能树节点就是工具名（人话）；价格 = 实时 token 表 |
| 学习曲线 | 前 3-5 关靠试错建立"我这手算哪类"的直觉 | 第一次施展就看懂："话说得准 → 轮次少 → 便宜" |
| 精通空间 | 记住价目表、算倍数 | **把话说准**（省轮次）+ **叫停时机**（省 token）——从"背价目"变成"练表达" |

净结论：**认知负荷显著下降，精通深度不降反升**。教程文案需从"七分类价目表"改为"天机型谱 + token 计价"口径（见 §6.5 文档同步清单）。

**预览信息量增强后的决策体验**（预览卡结构）：

```
│ ☯ 业力代价 62（68 → 130，安全线 120）                  │
│ 👁 识破风险 +10.9%（施展后立即结算一次）                 │
```

### 3.5 到点收尾与「收手」：同一收尾的两副面孔（策略 A UX 定稿）

**总规则（裁决 #3+#4 衔接定稿）**：主动收手（Esc/收手按钮）与被动超时（20s 到点）走**同一收尾函数、同一计价、同一契约**——`f(T_stop) × roll` 在预览时一次揭晓并锁定（Confirm 不重摇，A9），半成品价 ≤ 完整运行价（A7，f 单调非降保证）。区别只在**叙事措辞**（谁先动的手）与预览卡上的一条角标。工程暴露点：`AgentProgress.TimedOut` + 预览 `partial_note`（工程 §13.6）。

**三种结局 × 玩家可见表现**：

| 结局 | 触发 | 玩家可见表现 | 计价 |
|:--|:--|:--|:--|
| A-1 半成品预览 | 有写入（20s 到点 / 主动收手 / 轮次耗尽 / token 硬停） | 直接进 Preview 态：partial 角标 + banner + diff 卡（已落地的改动）+ 推演摘要（止于第 N 轮）+ 代价卡 | f(T_stop)×roll，预览揭晓锁定 |
| A-2 失败卡 | 零写入（同上任一触发） | 失败卡 + 建议（换个说法/拆两步/用预置指令）；不进计价 | **0**（无预览不收费） |
| A-3 取消预览 | partial 预览上点「取消」 | 回输入态，沙箱回滚 | **0**（沿用 E3：取消不扣费） |

**文案（天道叙事基调；主句同源，只改触发方那一句——速查条目同步入 §3.2 #16–18）**：

- **被动超时·有写入**（banner）：「天道力竭，推演半途而止——所得几何，造化自负。」角标：「时辰已到 · 天道自行收手 · 止于第 N 轮」。
- **主动收手·有写入**（banner）：「你及时收手，天道推演半途而止——所得几何，造化自负。」角标：「你收了手 · 省下的推演是自己造化」。
- **被动超时·零写入**（失败卡）：「天道力竭，此番推演，一事无成。妄念已散，不耗业力。」
- **主动收手·零写入**（失败卡，沿用 §1.7）：「你及时收手，天道推演半途而废。妄念已散，不耗业力。」
- 代价卡附行（半成品）：「业力 X（按已耗 N token 计价 · 预览一次揭晓，确认不重摇）」。

**为什么是"造化自负"而不是"失败"**：两段式契约下交付预览对玩家零成本（取消不收费），而 API 成本已沉没——丢弃它是纯亏；且 diff 卡比死胡同卡信息量更大。叙事上与裁决 #3 同哲学：**天道按实耗记账、不预判、不滥罚**——时辰到了是天道力竭，不是天道降罪；半成品要不要确认，由造化（玩家自己）决断。

**与投射顶格警示的叠加**：若 T_stop 已越过触顶（f(T_partial) ≥ 100 或外推越 120），计数器转红 + 顶格警示行，半成品预览按 clamp 120 显示（裁决 #3：放行 + 警示，不拦截）。

**音画接口**（阮和鸣）：到点收尾 = 一声闷响后静默（与收手同款），轨迹流末尾追加「（时辰已到）天道捻须，推演止于此处。」

### 6.2 对工程侧（程基岩）的要求

1. **token 计量**：复用现有 `LlmClient.TokenUsageCallback` / `OrchestratorEngine.RecordTokenUsage` 机制——每个 Agent 轮次的 usage（prompt+completion）累加为 T_eff，**completion 即含 thinking token**（DeepSeek 计费口径），无需拆分估计。
2. **上下文治理（校准成立的关键约定）**：工具结果进入历史后由宿主压缩为 ≈100 token 回执（阅后即焚，**入列时压缩、禁事后改写已有消息**）；系统提示+工具 schema 压到 ≈1,500 token，且必须**字节级稳定**（禁时间戳/nonce/会话 ID/动态数值入 system；历史 append-only；工具 schema canonical 序列化）——这是前缀缓存命中、TTFT ≤3s 的唯一保障（工程 §13.2 R1–R7，含 5 条门禁级单测）。若实测 S 显著高于此值，锚点需重拟——**先测 S，再拟合**。
3. **工具主机**：进程内 MCP host；门控在 schema 下发给 Agent 前过滤（§2.3）；白名单校验 + `SchemaValidator` 双保险；结构化错误供重试。
4. **可复现随机**：波动 roll 用 `DeterministicRng`，种子 = 会话种子 + 请求序号，写入日志（QA 回放）。
5. **流式（P2）**：`stream=true` 的 chunk 级 token 上报，供计数器连续跳动；P0 用轮级 usage 即可验收。
6. **`CheatController` 契约不动**：SubmitAsync(ct, onTrace, onTokenTick) / Confirm 唯一扣费；`CheatCostCalculator` 分档与识破公式原样。
