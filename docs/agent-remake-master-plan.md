## 3. 目标架构（详见工程文档 §2，此处仅索引）

```
玩家指令 ──→ CheatController.SubmitAsync ──→ AgentEngine（新增）
                                              │  while 轮次 ≤4 且 T_eff ≤60K 且 ≤20s
                                              │    ├─ LlmClient.ChatToolsAsync（tools=按技能过滤后的工具 schema）
                                              │    ├─ 工具主机：读工具(3) / 常规(3) / 特权写(2, 白名单+Schema+原子事务)
                                              │    └─ 错误回喂自愈 / TokenLedger 累计 / 顶格警示
                                              ▼
                      预览（轨迹 + 已耗 token + 预估业力 + 收手按钮）──玩家确认──→ Confirm：入改规栈 → 应用配置 → IncreaseKarma(clamp 值) → 溢出则 Detection
```

- 业力公式：`T_eff = Σ(prompt+completion, 含 thinking)`；有写入 `karma = clamp(round(f(T_eff) × σ × surge × 折扣), 1, 120)`，f 分段线性过设计锚点；零写入成功 → 恒 1
- 门控：`GetAllowedTools`（天机型谱，由技能节点推导）；装配点 `Bootstrap` 第 184 行换 `AgentEngine`
- 降级：离线/无 key → `OfflinePreview` 预置链路（旧值不动）

## 5. 性能 mandate 专项（20s 硬顶，详见工程文档 §13）

**延迟预算表（生产配置）**：本地装配 0.5s + 首轮 TTFT ≤3.0s / 生成 ≤2.0s + 第 2–4 轮均 ≤3.5s + 收尾预留 3.0s = **≤19.0s（余量 1.0s）**；P50 目标 ≤12s。反推配置：`MaxRounds=4`、工具轮 max_tokens 2,048 / 终轮 4,096、`HardTokenBudget=60K`、`ContextSoftCap=24K`。

| 手段 | 要点 |
|:--|:--|
| 前缀缓存最大化 | system 段（系统提示 + 工具 schema）**字节级稳定**：禁时间戳/请求变内容/HashSet 枚举序；「阅后即焚」必须在**入列时**压缩（入列后改写即使内容等价也废缓存）；验收：第 2 轮起前缀命中率 P50 ≥90%（A1–A5 单测断言） |
| thinking 压缩 | 默认 **M2**（工具轮 low + 终轮 high）；M1/M3/M4 为实验矩阵（E3-S2，需授权） |
| 轮次压缩 | 工具设计促使批量操作（一次 apply 多 patch）、提示词引导；典型任务目标 2–4 轮 |
| 流式进度 | P0 轮级 usage 可验收；P1 chunk 级连续计数器（对齐设计 §6.2） |
| 20s 收尾 | **策略 A（尽力交付）**：有写入 → 半成品预览按 `f(T_stop)` 计价；无写入 → 失败卡不收费；主动收手与被动超时同价同叙 |
| 超支降级序 | 终轮 effort → max_tokens → 轮数 → 工具轮 none，只改 json；触发降级须回 §6 第 0 步重认校准 |
